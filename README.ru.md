# ProxyRules

[English](README.md) | **Русский**

Маршрутизация трафика на роутере OpenWrt через [sing-box](https://sing-box.sagernet.org/) по одному файлу правил: какие домены, адреса и устройства идут через какое соединение (VLESS/REALITY или интерфейс вроде AmneziaWG/WireGuard), с автоматическим переключением на живое соединение и страницей в LuCI для управления.

```
DE   = vless://…
NL   = vless://…
AUTO = DE,NL                       # первое живое по порядку

protocol:bittorrent                -> direct
domain:example.com                 -> NL
list:youtube, discord              -> AUTO
src:192.168.1.50                   -> AUTO
```

Всё, что не подошло ни под одно правило, идёт напрямую — через прокси идёт только то, что вы указали.

## Возможности

- **Один понятный файл правил** — `/etc/proxyrules.conf`; страница в LuCI правит этот же файл и сохраняет ваши комментарии и форматирование.
- **Правила по домену, списку доменов, IP/подсети, устройству в сети, порту и протоколу**, с сочетаниями через `&` («и») и `!` («не»); срабатывает первое подходящее правило.
- **Готовые списки доменов** (YouTube, Discord, Meta, Telegram, …) из [itdoginfo/allow-domains](https://github.com/itdoginfo/allow-domains), обновляются раз в сутки.
- **Цепочки с переключением** — `AUTO = DE,NL` использует первое живое соединение и возвращается на более приоритетное, когда оно оживает.
- **Соединения**: VLESS-ссылки (REALITY, TLS; транспорты tcp, ws, grpc, httpupgrade, http) в том виде, как их выдал сервер, или любой интерфейс OpenWrt (AmneziaWG, WireGuard, …).
- **В sing-box попадает только нужный трафик**; всё остальное идёт напрямую на полной скорости.
- **Проверка до применения** — конфиг проверяется (включая `sing-box check`) до сохранения; ошибки указывают на строку.
- **Установка одной командой, обновление из LuCI, удаление одной командой.**
- **Интерфейс на русском и английском.**

## Требования

- OpenWrt **24.10 или новее** (opkg или apk), с LuCI.
- Место во флеше под `sing-box`: сам файл около 40 МБ (на сжатом overlay занимает меньше). Свободное место — `df -h /overlay`.
- Оперативная память: sing-box с загруженными списками занимает около 70 МБ. Рекомендуется 256 МБ и больше; на роутерах со 128 МБ будет впритык.
- Хотя бы один прокси-сервер: VLESS-ссылка (например, из 3x-ui / x-ui / Xray) или VPN-интерфейс, уже настроенный в OpenWrt.
- Для VLESS REALITY на сервере нужен Xray-core **старее 26.9.8**. Новые версии отклоняют REALITY-подключения от sing-box 1.12 (`reality verification failed`, см. [SagerNet/sing-box#4520](https://github.com/SagerNet/sing-box/issues/4520)). 3x-ui ставит более новое ядро, поэтому замените `/usr/local/x-ui/bin/xray-linux-amd64` на старый релиз (например, v25.9.11) и перезапустите x-ui — и так после каждого `x-ui update`.

Недостающие пакеты установщик ставит сам: `sing-box`, `ucode`, `ucode-mod-fs`, `rpcd-mod-ucode`, `jq`, `curl`, `ip-full`, `kmod-nft-tproxy`.

## Установка

Зайдите на роутер по SSH (`ssh root@192.168.1.1`) и выполните:

```sh
wget -qO- https://github.com/m0n5ter/ProxyRules/releases/latest/download/install.sh | sh
```

Установщик:

1. спрашивает язык интерфейса (английский или русский) — только при первой установке;
2. ставит недостающие пакеты (`opkg update` / `apk update` запускается, только если чего-то не хватает);
3. скачивает последний релиз и раскладывает файлы;
4. если `/etc/proxyrules.conf` ещё нет, кладёт туда пример (с комментариями на выбранном языке);
5. добавляет в LuCI пункт **Службы → Proxy Rules**.

Сам сервис при этом не запускается — только когда вы нажмёте **Запустить**.

Чтобы выбрать язык без вопроса, добавьте `--lang ru` или `--lang en`:

```sh
wget -qO- https://github.com/m0n5ter/ProxyRules/releases/latest/download/install.sh | sh -s -- --lang ru
```

Чтобы поставить конкретную версию, укажите её тег:

```sh
wget -qO- https://github.com/m0n5ter/ProxyRules/releases/latest/download/install.sh | sh -s v1.1.0
```

## Первая настройка

1. Откройте **LuCI → Службы → Proxy Rules**. Если пункта нет, выйдите из LuCI и зайдите снова.
2. Вкладка **Соединения**: замените примеры `DE` и `NL` на свои. Вставьте ссылку `vless://…` целиком, как её выдал сервер, или укажите интерфейс (`iface:awg0`). Удалите соединения, которых у вас нет.
3. Вкладка **Цепочки**: задайте порядок, в котором пробуются соединения, например `AUTO = DE,NL`.
4. Вкладка **Правила**: удалите ненужные примеры и добавьте свои. IP своих серверов поставьте в правило `-> direct` в самом верху.
5. Вкладка **Настройки**: проверьте `@interfaces` — интерфейсы LAN, трафик которых перехватывается (обычно `br-lan`).
6. Нажмите **Проверить**, затем **Сохранить и применить**.
7. Вкладка **Статус**: нажмите **Запустить**. Через несколько секунд соединения должны показаться работающими, а у цепочек будет видно, какое соединение используется.

## Страница в LuCI

| Вкладка | Что там |
| --- | --- |
| **Статус** | Версия и проверка обновлений, состояние сервиса и кнопки Запустить / Остановить / Перезапустить, состояние и задержка каждого соединения, какое соединение сейчас выбрано в каждой цепочке, обновление списков. |
| **Правила** | Правила по порядку. Перетаскивание, группы под заголовками, правка условий и целей прямо в списке. |
| **Соединения** | Добавление, переименование (ссылки на имя обновляются тоже) и правка соединений. Секреты из ссылок в списке не показываются. |
| **Цепочки** | Именованные цепочки и их порядок. |
| **Настройки** | Настройки `@` и язык интерфейса. |
| **Файл конфигурации** | Файл как есть, для правки вручную. |

Язык интерфейса можно сменить в любой момент на вкладке **Настройки** (**Язык интерфейса**); от него зависит и язык сообщений об ошибках. Он хранится в `/etc/proxyrules/lang`.

**Проверить** — проверка файла без сохранения. **Сохранить и применить** — проверка, сохранение и перезапуск сервиса, если он работает. **Отменить** — отбросить несохранённые изменения.

## Файл конфигурации

`/etc/proxyrules.conf`. Полный пример с комментариями — [files/etc/proxyrules.conf.example.ru](files/etc/proxyrules.conf.example.ru) (на роутере — `/etc/proxyrules.conf.example.ru`).

Комментарий — `#` в начале строки или после пробела. В именах — латинские буквы, цифры и `-`; `direct` и `block` зарезервированы.

### Соединения

```
ИМЯ = vless://…             ссылка целиком, как её выдал сервер
ИМЯ = iface:awg0            интерфейс OpenWrt: AmneziaWG, WireGuard, …
```

Поддерживаемые параметры VLESS: `security=reality|tls|none`, `type=tcp|ws|grpc|httpupgrade|http`, `flow`, `sni`, `fp`, `pbk`, `sid`, `alpn`, `path`, `host`, `serviceName`. VLESS Encryption (`encryption=mlkem768…`) sing-box не поддерживает — поставьте у inbound на сервере Decryption = `none`.

### Цепочки

```
AUTO    = DE,NL             первое живое соединение по порядку
NL-SAFE = NL,direct         если NL лежит — напрямую
```

Роутер проверяет каждое соединение раз в `@check_interval` секунд. Цепочка использует первое живое; когда более приоритетное оживает, цепочка возвращается на него. В цепочке только соединения и `direct` — цепочки не вкладываются. Если лежат все, sing-box сам ищет живое.

### Правила

```
условие [& условие…] -> ЦЕЛЬ
```

Правила проверяются **сверху вниз, срабатывает первое подходящее**. Всё остальное идёт напрямую.

| Условие | Что подходит |
| --- | --- |
| `domain:example.com` | домен и все его поддомены |
| `list:youtube` | список из itdoginfo/allow-domains (домены и подсети): `anime block cloudflare cloudfront digitalocean discord geoblock google_ai google_meet google_play hdrezka hetzner hodca meta news ovh porn roblox russia_inside russia_outside telegram tiktok twitter ukraine_inside youtube` |
| `ip:203.0.113.0/24` | адрес или подсеть назначения |
| `src:192.168.1.50` | устройство в LAN (или подсеть) — весь его трафик |
| `port:443, 50000-65535` | порт или диапазон назначения (TCP и UDP) |
| `protocol:bittorrent` | определяется по первым пакетам: `bittorrent tls http quic stun dtls ssh rdp ntp` |

- Несколько значений через запятую — «или»: `domain:a.com, b.com`.
- `&` — «и»: `src:192.168.1.50 & domain:example.org -> DE` — только это устройство и только этот сайт.
- `!` — «не»: `!src:192.168.1.50 & domain:example.org -> block` — все, кроме этого устройства.
- Хотя бы одно условие должно быть без `!` (кроме правил с целью `direct`).
- `protocol:` виден только в трафике, который и так идёт в sing-box, поэтому сам по себе работает только с `-> direct` (ставьте его выше правил, которые он должен перебить). С другими целями добавьте ещё условие: `src:… & protocol:quic -> block`.

| Цель | Значение |
| --- | --- |
| `AUTO` | цепочка |
| `NL` | одно соединение, без запасных |
| `NL,DE` | цепочка без имени, прямо в правиле |
| `direct` | напрямую, без прокси |
| `block` | заблокировать |

### Настройки

| Настройка | В примере | Значение |
| --- | --- | --- |
| `@interfaces` | `br-lan` | интерфейсы LAN, трафик которых перехватывается (через пробел) |
| `@dns` | `8.8.8.8` | DNS-over-HTTPS сервер (IP или имя) |
| `@bootstrap` | `77.88.8.8` | обычный DNS, через который узнаётся адрес DoH-сервера (IPv4) |
| `@check_url` | `https://www.gstatic.com/generate_204` | адрес для проверки соединений |
| `@check_interval` | `10` | секунд между проверками соединений (5–3600) |
| `@lists_via` | `AUTO` | соединение или цепочка, через которые скачиваются списки `list:` |
| `@log` | `warn` | уровень лога sing-box: `trace debug info warn error` |

## Как это работает

- **DNS.** dnsmasq отдаёт все запросы в sing-box. Домены из правил получают *fake IP* из `198.18.0.0/15`; остальные разрешаются обычным образом через DoH. Исходные настройки dnsmasq сохраняются и возвращаются при остановке.
- **Перехват.** Таблица nftables (`inet proxyrules`) помечает трафик на fake IP, на подсети из списков `list:` и трафик, подходящий под правила `src:`/`ip:`/`port:`, и отдаёт его в sing-box через TPROXY. Всё остальное до sing-box не доходит.
- **Маршрутизация.** sing-box применяет правила в том же порядке и отправляет каждое соединение в его цель.
- **Сторож.** Небольшой процесс проверяет соединения через API sing-box, переключает цепочки, раз в сутки обновляет списки и пишет статус для LuCI.

Перехватывается только IPv4.

Файлы на роутере:

| Путь | Что там |
| --- | --- |
| `/etc/proxyrules.conf` | ваши правила |
| `/etc/proxyrules/` | скачанные списки, сохранённые настройки dnsmasq и язык интерфейса |
| `/var/run/proxyrules/` | сгенерированный конфиг sing-box, правила nftables и статус (создаются заново при запуске) |
| `/usr/share/proxyrules/` | генератор, сторож, установщик и версия |

## Обновление

**Из LuCI:** вкладка **Статус** → **Проверить обновления**. Если есть релиз новее, нажмите **Обновить**: он скачается, установится, сервис перезапустится (если работал), а страница перезагрузится. `/etc/proxyrules.conf` не меняется.

**По SSH:** выполните команду установки ещё раз.

## Удаление

По SSH на роутере:

```sh
sh /usr/share/proxyrules/install.sh uninstall
```

Команда останавливает сервис, возвращает исходные настройки dnsmasq и удаляет proxyrules и его страницу в LuCI. `/etc/proxyrules.conf` и `/etc/proxyrules/` остаются — при повторной установке всё продолжит работать как было. Чтобы удалить и их:

```sh
sh /usr/share/proxyrules/install.sh uninstall --purge
```

То же без локальной копии:

```sh
wget -qO- https://github.com/m0n5ter/ProxyRules/releases/latest/download/install.sh | sh -s uninstall
```

Пакеты, поставленные для proxyrules (`sing-box` и другие), остаются; удалите их через `opkg remove` / `apk del`, если они больше ничему не нужны.

## Если что-то не работает

- **Что-то сломалось и интернет нужен прямо сейчас:** **Остановить** на вкладке «Статус» или `/etc/init.d/proxyrules stop` по SSH. Трафик пойдёт напрямую, настройки dnsmasq вернутся.
- **Логи:** `logread -e proxyrules` (сервис, сторож и установщик) и `logread -e sing-box`.
- **Сервис не запускается:** причина видна на вкладке «Статус»; она же в `/var/run/proxyrules/error`.
- **Соединение всё время лежит:** откройте ссылку в клиенте на компьютере, чтобы убедиться, что сервер работает; проверьте время на роутере (`date`) — REALITY не работает, если часы сбиты.
- **Сайт всё равно открывается напрямую:** устройство может использовать свой DNS (DoH в браузере или прописанный вручную DNS-сервер) и не получает fake IP. Отключите «безопасный DNS» в браузере или добавьте правило `ip:`/`src:`.
- **Статус в JSON:** `ubus call proxyrules status`.

## Разработка

`router.sh` ставит рабочую копию на роутер по SSH (по умолчанию `root@192.168.1.1`, меняется через `HOST=…`):

```sh
./router.sh update      # собрать из рабочей копии и установить; конфиг и сервис не трогаются
./router.sh start       # (пере)запустить с проверкой; если проверка не прошла — остановить
./router.sh stop
./router.sh uninstall
```

`tools/build.sh OUT.tar.gz [ВЕРСИЯ]` собирает архив релиза; версия по умолчанию — из `git describe`.

Релиз: `git tag v1.2.0 && git push origin v1.2.0`. GitHub Actions соберёт `proxyrules.tar.gz` и опубликует его вместе с `install.sh`.
